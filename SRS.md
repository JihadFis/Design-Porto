# Software Requirements Specification (SRS)
**Project:** Portofolio Website - Jihad Fisabilillah
**Course:** Pemrograman Web (UTS)
**Version:** 2.0

## 1. Introduction

### 1.1 Purpose
This document describes the requirements of a personal portfolio website that presents the owner's design and illustration work to visitors such as potential clients and collaborators.

### 1.2 Scope
A static, single-page website built with HTML, CSS and JavaScript and hosted on GitHub Pages. It has no backend or database. It displays information and images, and offers a contact form with client-side validation.

### 1.3 Definitions
- **DOM:** the browser's tree representation of the HTML page.
- **Static site:** a site whose content is fixed in the HTML files and not generated by a server.
- **Placeholder:** a temporary image that is replaced with real artwork later.

## 2. Overall Description

### 2.1 Product perspective
A standalone front-end website with no external data source. All content is written in `index.html`, and images are stored in the `images/` folder.

### 2.2 User classes
| User | Description |
|---|---|
| Visitor | Anyone viewing the portfolio, no login required |
| Owner | Edits the HTML file and replaces the images to update content |

### 2.3 Operating environment
Any modern browser (Chrome, Firefox, Edge, Safari) on desktop or mobile.

### 2.4 Constraints and assumptions
- Uses only HTML, CSS and JavaScript (no frameworks).
- Hosted on GitHub Pages (static files only).
- The contact form does not deliver an email; it validates the input and shows a "Message sent" notice.
- Images are placeholders until the owner replaces them.

## 3. Functional Requirements

| ID | Requirement |
|---|---|
| FR-01 | The system shall show a header with a title ("Hello!") and a short description. |
| FR-02 | The system shall provide a navigation menu with at least two links (Projects, Contact). |
| FR-03 | The system shall show an "about me" section with a description and software icons. |
| FR-04 | The system shall show a portfolio section with project images. |
| FR-05 | The system shall show a list of group logos the owner has worked with. |
| FR-06 | The system shall provide a contact form with name, email and message fields. |
| FR-07 | The system shall validate the form and show an error message for each invalid field. |
| FR-08 | The system shall show a "Message sent" notice when the form is valid. |
| FR-09 | The system shall play hover animations on cards, icons, logos, the hero title and buttons. |

## 4. Non-Functional Requirements

| ID | Requirement |
|---|---|
| NFR-01 | **Usability:** the layout shall be readable and consistent (high-contrast text, simple structure). |
| NFR-02 | **Responsiveness:** the layout shall adapt from small phone screens to desktop width. |
| NFR-03 | **Performance:** the page shall load quickly since it uses no external libraries. |
| NFR-04 | **Compatibility:** the page shall work in current versions of major browsers. |
| NFR-05 | **Standards:** HTML and CSS shall pass the W3C validators. |
| NFR-06 | **Maintainability:** HTML, CSS and JS shall be in separate files, and images shall be replaceable without changing the layout. |
| NFR-07 | **Accessibility:** every image shall have an `alt` text and every form field a label. |

## 5. System Design Overview

### 5.1 Structure
```
Browser -> index.html -> style.css   (look)
                      -> script.js   (contact form behaviour)
                      -> images/*    (placeholders / artwork)
```

### 5.2 Page sections (top to bottom)
1. Header: navbar + hero
2. About me + software icons
3. Portfolio (3 project images)
4. Groups I've worked with (logos)
5. Contact form
6. Footer

### 5.3 Main flow: contact form
Visitor submits -> `preventDefault()` -> name, email and message are validated -> errors are shown, or the "Message sent" notice appears and the form is cleared.

## 6. Test Cases

| ID | Action | Expected result |
|---|---|---|
| TC-01 | Open the page | Header, About, Portfolio, Groups, Contact and Footer are shown |
| TC-02 | Click "Projects" or "Contact" in the nav | Page scrolls to that section |
| TC-03 | Hover over a project card | Card lifts up with a shadow |
| TC-04 | Submit an empty form | Three error messages appear, nothing is sent |
| TC-05 | Enter an invalid email | Email error appears |
| TC-06 | Start typing in a field with an error | That field's error disappears |
| TC-07 | Submit a valid form | "Message sent" notice appears and the form is cleared |
| TC-08 | Resize below 600 px | Cards stack and spacing shrinks without horizontal scrolling |
